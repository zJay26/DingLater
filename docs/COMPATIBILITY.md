# DingLater 兼容性与验收状态

## 支持基线

- Windows 10 `19041` 或更新版本，x64。
- WinUI 3、.NET 10 与 Windows App Runtime 自包含便携版。
- 钉钉桌面版 `8.3.45.260720005`，`*_v3` 数据目录、4096 字节 AES 分页数据库和对应 V3 schema。

兼容性按实际能力探测：密钥必须解出 `SQLite format 3`，DB/WAL 必须通过完整性检查，核心表、字段和 128 个分表必须全部存在。客户端版本变化但格式完全一致时允许继续；任一能力不匹配即停止捕获并给出稳定错误码。

不支持 V2、macOS、移动端、附件下载、历史导入，以及钉钉未同步到本机数据库的消息。钉钉必须已登录；应用可以在钉钉重启和 WAL 轮换期间自动重试。

## 窗口置顶

- 全局快捷键默认 `Ctrl + Win + T`；置顶在 DingLater 隐藏到托盘后继续生效，不依赖消息捕获是否暂停。
- 使用 Windows 原生置顶及进程外窗口事件，不增加进程、系统服务或定时扫描。描边不接收鼠标、不抢焦点，颜色使用系统高亮色，厚度随目标窗口 DPI 缩放。
- 正常退出默认恢复本次由 DingLater 设置的置顶；原本已置顶且未被操作的窗口保持原状。可在设置中关闭退出恢复；关闭功能开关仍会取消本次的置顶。
- 权限更高的窗口、其他置顶窗口、独占全屏和自行管理窗口层级的应用存在 Windows 平台限制。快捷键冲突会明确提示，不会停止消息捕获。
- 原生窗口测试覆盖置顶切换、多窗口、描边区域与穿透样式、移动/缩放、最小化/恢复、目标销毁、外部取消置顶、关闭功能、退出恢复和快捷键冲突。多显示器混合 DPI、虚拟桌面及第三方特殊窗口需现场验证。
- 2026-09-22 在本机 Windows build 26200 的隔离合成数据实例中，已现场检查快捷键触发的描边、置顶时点击设置、关闭开关取消置顶，以及主窗口隐藏到托盘后对另一进程窗口的置顶、最大化跟随与再次按键取消。现场自动化使用测试组合键，生产组合键仍为 `Ctrl + Win + T`。

## 双账号验收

1. 接收端退出旧 DingLater，启动便携版并确认健康状态为“可用”。
2. 记录目标会话未读数，发送端发送短文字、超过 200 字文字、emoji/换行和连续两条相同文字。
3. 不打开钉钉目标会话，只在 DingLater 查看、搜索、稍后和标记处理。
4. 确认 DingLater 在 10 秒内分别显示完整消息，接收端未读数与发送端回执没有变化。
5. 图片/语音/文件只检查占位与文件名，不期待附件内容。

## 界面验收矩阵

使用 Debug `--demo` 合成消息检查 `640×520`、`920×700`、`1180×740`、`1600×900`，并覆盖四档字号、Light/Dark/High Contrast 和 Windows 文字缩放 `100%/150%/225%`。验收时确认无水平滚动、正文完整换行、操作可达、列表仍虚拟化，且窄屏详情可通过返回按钮与 `Alt+Left` 返回。
