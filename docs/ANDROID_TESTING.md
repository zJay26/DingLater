# Android 真机验收清单

源码编译、自动测试和 APK 构建不能证明当前钉钉版本一定提供完整通知载荷。以下步骤必须由用户在真实手机和真实账号上执行，并记录手机型号、Android 版本、钉钉版本、钉钉通知详情设置和省电策略。

## 前置检查

- 全新安装或先在 DingLater 中删除全部本地数据。
- 授予 DingLater 通知使用权；Android 13 及以上分别记录提醒通知为允许和拒绝时的表现。
- 准备发送账号与接收账号各一个，接收端保持钉钉登录。
- 验收开始前记下设置页诊断计数，确保测试通知发生在“开始记录新通知”之后。

## 载荷矩阵

每项分别检查：会话名、发送者、正文、换行/Emoji、消息条数、时间、是否显示“内容可能不完整”。

| 维度 | 测试值 |
|---|---|
| 文本长度 | 1、200、500、2000 字 |
| 字符 | 中文、英文、Emoji、连续换行 |
| 连续消息 | 同一会话连续发送 2–5 条，包含相同正文；确认第一条之后仍能持续捕获 |
| 会话 | 私聊、普通群聊、群聊 @我、群聊 @所有人 |
| 钉钉状态 | 前台、后台、进程被系统回收后重新通知 |
| 手机状态 | 亮屏、锁屏、省电模式 |
| 通知设置 | 显示详情、隐藏敏感内容、关闭会话通知 |

Android 版不提供“群聊仅收 @我”开关；实际范围完全服从钉钉和系统展示出来的通知。隐藏或截断时允许继续保存，但必须明确显示降级标记。

## 必过行为

1. 授权前已有通知不进入 DingLater；授权完成后新通知才进入。
2. 非钉钉通知不出现在列表，且不会增加钉钉正文诊断。
3. 收到通知不会打开钉钉、消除原通知、触发已读或执行通知操作。用发送账号确认接收状态。
4. 暂停捕获后新通知不保存；恢复后只保存恢复之后的新通知。
5. 撤销通知使用权立即停止捕获，设置页正确显示未授权。
6. 截断、隐藏详情或仅有单行文本时显示“内容可能不完整”，不会补写或猜测正文。
7. 单条稍后提醒、标为已处理、恢复、删除和三个分类中的批量操作结果正确。
8. 提醒时间不早于设定时间；省电模式允许延迟。重启手机和覆盖安装后，未来提醒仍能恢复。
9. Android 13 及以上拒绝 DingLater 通知权限后，到期消息仍回到“待处理”，但系统不弹提醒；设置页显示未授权。
10. 点击 DingLater 提醒只打开对应本地消息，不启动钉钉。
11. 修改保留期后，到期消息被删除；“删除全部”同时清空本地消息与失效的提醒入口。
12. 系统字体缩放、Light/Dark 下内容可读，底部导航和主要操作不被裁切。
13. 覆盖安装修复版后，不清空旧消息直接连续发送至少 5 条；全部通知都应被观察，且某一条解析失败时后续消息仍能继续进入。设置页“单条失败”允许增加，但不应变为永久停止。

## 自动验证范围

- JVM：通知字段优先级、空载荷/群摘要过滤、降级质量、提醒恢复筛选，以及普通异常不会永久停止捕获。
- 设备测试：Room 去重/状态/到期清理、schema v1 基线、Android Keystore AES-GCM 往返与随机 nonce、HMAC 稳定性、首次启动关键说明。
- Lint/Manifest：禁止网络、Accessibility、存储读取、精确闹钟权限；备份关闭；API 29 兼容检查。
- APK：Debug 签名、版本号、权限清单与 SHA-256。

真实钉钉通知载荷、端到端未读表现、厂商省电策略和锁屏隐私行为不在自动测试能证明的范围内，必须以本清单的真机结果为准。
